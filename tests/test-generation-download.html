Tests generation & telechargement Caramel

Prechargement → structuredClone → H5P Blob → Moodle MBZ → XML/GIFT → Visualisation → Lookup map → Export doc

Comment ca marche ?

Objectif : Tester le flux complet de generation, telechargement et visualisation. Verifie aussi les optimisations de performance (prechargement, structuredClone, lookup map).

  1. Prechargement — Import dynamique des modules JS et chargement des bibliotheques externes (client-zip, fflate, JSZip, DOMPurify, h5p-standalone).
  2. structuredClone — Equivalence entre structuredClone() et JSON.parse(JSON.stringify()) pour tous les fichiers d'exemple.
  3. H5P Blob — Pipeline complet : heal → process → createH5PBlob → relecture ZIP (content.json, h5p.json, dependances) → simulation telechargement (objectURL).
  4. Moodle MBZ — Pipeline complet : heal → buildMoodleData → getActivityFiles → createMbz → decompression TAR (moodle_backup.xml) → simulation telechargement.
  5. XML/GIFT — Generation Moodle XML (banque de questions) et GIFT pour les activites elea_test + glossaire XML.
  6. Visualisation — Smoke test : relecture du blob H5P, verification de la structure JSON specifique au type, coherence mainLibrary/dependances.
  7. Lookup map — Construction de la map modulesByTitleKey comme dans ui.js, verification unicite des cles, champs requis H5P et Moodle.
  8. Export doc — Appel de formatContentForDocument() pour chaque activite : verifie titre, sections (paragraphes, tableaux, cartes flash...), types valides. Couvre les exports DOCX, ODT, PDF.

Donnees : fichiers JSON de assets/data/examples/. Memes cas de test que test-edit-export-flow.js.
