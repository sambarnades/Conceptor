Tests pipeline complet Caramel

JSON brut IA → Healer → Processeur → Math pre-edit → Editeur → Sauvegarde → Re-export → Math post-edit

Comment ca marche ?

Objectif : Tester le pipeline complet de bout en bout. Le JSON brut genere par l'IA traverse 8 etapes, chacune verifiee individuellement.

  1. Chargement — Lecture du fichier JSON brut depuis assets/data/examples/.
  2. Healer — healJsonString → parse → healJsonObject → healActivitySpecificFields → healStructureForActivity + detection + schema.
  3. Generation — Processeurs H5P / Moodle + creation et relecture du blob ZIP/MBZ + verification LaTeX et structure.
  4. Math pre-edit — Tests synthetiques + exemples existants : verifie l'encodage math avant l'editeur. Detecte double-echappement, verifie MathJax/Unicode.
  5. Edition — normalizeDataForEditor + simulation modification utilisateur (marqueur __EDITED_BY_TEST__).
  6. Sauvegarde — denormalizeDataForSave + verification marqueur + textes originaux preserves + LaTeX.
  7. Re-export — Re-heal + re-processing + nouveau blob. Marqueur, structure, LaTeX verifies.
  8. Math post-edit — Verifie que les formules survivent au round-trip complet (edit → save → re-export). Comparaison pre/post.

Donnees : fichiers JSON de assets/data/examples/. Pour ajouter un type, ajouter une entree dans testCases de tests/test-edit-export-flow.js.
