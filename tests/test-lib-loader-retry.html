Tests lib-loader retry

Verifie le mecanisme de retry apres echec de chargement des bibliotheques

Contexte du bug corrige

Probleme : Si le preloading d'une bibliotheque echouait (reseau instable), la promesse rejetee restait en cache dans loadPromises. Tous les appels suivants reutilisaient cette promesse rejetee, causant l'erreur "Une erreur est survenue lors du traitement" jusqu'au rechargement de la page.

  1. loadScript : marque les scripts avec data-loaded (true/false), retire et recree les scripts echoues
  2. load*Libs : ajout d'un .catch() qui supprime la promesse du cache (delete loadPromises.xxx)
  3. Idempotence : tous les loaders fonctionnent correctement en appels multiples
